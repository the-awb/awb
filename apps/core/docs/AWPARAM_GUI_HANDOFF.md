# AWParam GUI implementation handoff

Create a reusable AWB Shell control for AWParam: an editable base knob, an editable modulation-amount ring, a Bitwig-style line showing the actual output, and an accessible panel for modulation sources. The control must embed in instrument, Chain and Core panels and be invokable through the SC Tool bridge. Keep live numeric observation compact and coalesced; changing one parameter must not rebuild the surrounding panel.

## Remaining work to completion

The broker already provides shared subscriptions and a latest derived-frame cache. AWParam has language-side caches populated by its existing OSC replies; AWModulationRegistry records producers and connections, not their current values. Reuse the broker rather than create a parallel registry. The following five pieces remain pending:

1. **Latest control-value interface on the broker.** Add shared output-bus subscriptions, cached latest scalars, freshness and compact changed-value batches at 8/15 Hz. Identify values by host/binding generation and bus; release them with their last lease. Send no history to the widget. Distinguish the first adapter over existing capture from any later optimisation that avoids upstream history acquisition/copy work.
2. **Parameter-level change notifications.** Publish base, amount and curves independently when changed, with transition descriptors where needed. Update the affected AWBCoreTool configuration entry without rebuilding/transmitting every parameter during dragging. Keep full snapshots for connection/recovery and explicit export.
3. **Source editing APIs.** Add validated public per-source amount/curve setters, updating both the route synth and retained metadata. Expose source identity, producer, capabilities, connection status and lifecycle changes. Preserve existing DSP mathematics and borrowed-resource ownership.
4. **GUI and Tool binding.** Build the base knob, signed amount ring, effective-output arc and accessible source panel. Support next-frame local editing, keyboard/numeric access, parent Tool embedding and invocation from sclang. Provide matching SVG and shared Canvas2D versions using the same model and compact feed.
5. **Verification and delivery.** Prove transport behaviour with 16/32/128 independent parameters before polishing both renderers; then compare identical visuals and qualify the integrated GUI/bridge under audio load when the engine slot is reserved. Deliver focused tests, working examples, rebuilt consumed artifacts and measured results with outstanding gates clearly identified.

Complete the infrastructure in items 1–3 and its early transport check before GUI polishing. These interfaces should also serve rack, Chain and instrument panels. Completion requires all five pieces and the acceptance checks below; writing this handoff does not mark any implementation or live qualification as complete.

## Agreed interface

Use the normal shell stack, React for composition and accessible controls. Keep the appearance compact, dark and consistent with the rack. Implement matching HTML/SVG and shared Canvas2D renderers against one state model for comparison. SVG is the first usable implementation; final renderer selection follows measurement. The preferred output cue is a Bitwig-style line or arc. Opacity is an optional overview/benchmark alternative. A dot is not the preferred output indicator.

| Element | Meaning and interaction |
|---|---|
| Knob and value field | Edit base value in native ControlSpec units. Pointer drag and keyboard/numeric editing update the live SC parameter. |
| Amount ring and numeric field | Edit AWParam's overall signed modulation amount. This is a fraction of the full normalized parameter range, not a native-unit offset. |
| Thin output line or arc | Read-only effective output. Trace the displacement from the current base position to the actual output position; use a distinct colour from the editable amount ring. Zero displacement remains discernible as a short radial line. |
| Modulation button and source count | Open the source panel. Indicate invalid/pending connections without relying on colour alone. |
| Modulation panel | Edit overall modulation curve and each standard source route's signed amount/curve; identify producing processes and connection status. |

Show base, global amount and effective-output numbers when the panel is open. Compact knobs retain the editable base field and make amount/output available on focus or expansion. The effective output is never an editable control. Knob and ring interaction areas must be distinct; clicking the output cue must not accidentally edit amount.

The base and global amount can themselves be transitioning. Send their transition descriptors once when changed, rather than retransmitting both on each output sample. Animate their indicators locally from the descriptor, while edit fields retain the user's in-progress text. Distinguish target, estimated ramp progress and measured output. An interrupted transition needs a truthful start anchor or an explicitly estimated display; do not label reconstructed progress as server readback. Any necessary one-shot anchor/completion read is separate from the recurring output feed.

Use `ControlSpec.unmap` semantics for both base and output positions. Linear and exponential parameters must agree with SC. Global and per-route amounts currently accept -8..8 and curves -16..16, with 0 representing a linear curve. Do not silently limit valid amounts to -1..1; make direction, magnitude and magnitudes above one full range readable, with a numeric field available. Use a signed ring with zero at its centre reference: opposite directions represent negative and positive amounts, and each direction saturates visually at magnitude 1. Beyond ±1, retain the saturated arc and show an overflow mark plus the signed numeric magnitude; do not draw overlapping revolutions. Use this same rule in both renderers. The amount ring represents its configured amount; it does not promise a reachable min/max because several sources, their ranges, curves and final clipping affect that.

## Modulation panel

The panel may expand inline or open as an anchored popover. It must fit inside the shell window, scroll independently when needed and preserve the surrounding panel layout. Opening it by keyboard moves focus into it; closing returns focus to the opener. Tab cycles fields, Enter commits numeric edits, Escape cancels an uncommitted edit or closes the panel, and arrow keys operate focused range controls without trapping normal text editing.

Each source row includes:

- A stable connection ID and readable source name. Display the source bus/producer identity as secondary information; a process link selects or opens the relevant NodeManager item when available.
- Signed amount and numeric curve controls. A small static curve preview updates when the curve changes. Keep source and overall controls clearly labelled.
- Pending, connected, removed or invalid status with a readable reason where supplied. A pending connection must not look active before validation completes.
- For a registered source, its declared producing Synth or Group; for an owned writer, its tracked node/definition; for an unregistered borrowed bus, a truthful bus label with producer unknown.

Registered routes and ordinary bus routes should expose amount/curve editing through the same API. Arbitrary custom writers may implement their own transformation inside their SynthDef; their row must indicate custom controls and expose only declared editable fields. Do not manufacture a generic amount or curve that the writer does not have. Retain access to its producing process. Live per-source meters, adding/removing sources and graph editing are follow-up features; the first panel documents and edits existing standard routes.

Source amounts/curves act before sources sum. AWParam's overall amount/curve act on the combined input. Never substitute one for the other or multiply the source amount into the global amount behind the user's back. Preserve the current DSP order and curve mathematics, including the existing extension beyond one summed input range and output clipping. Curve preview code must match the SC shaping function for its declared domain.

- [AWModulationRegistry.sc](../sc/classes/AWModulationRegistry.sc): named borrowed sources, producer/order validation, connection records, lifecycle cleanup and `content`.
- [AWBCoreTool.sc](../sc/classes/AWBCoreTool.sc) and [Core README](../README.md): ToolInstance ownership, named params, registry, configuration/state handling and embedding boundary.
- [Rack connection](../../rack/src/connection.mjs): local/remote origin handling and 16 ms batching; reuse the architectural pattern without coupling this widget to rack-specific control IDs.
- Shell `services/oscWebSocketRelay.mjs`, `services/nodeManagerProjection.mjs`, Tool GUI contracts and existing hosted tools: host identity, binding, reconnects and projection recovery.

One AWParam currently owns an input bus, output bus, processor and ordered source subgroup. Its processor clears the modulation input after reading. Observe the effective output/state; do not scope the transient cleared input bus as if it were a reliable aggregate-modulation meter.

The processor's existing `/awb/param/state` reply contains current base, global amount, effective output and two serials. This GUI must not enable that periodic reply as its normal observation path. Keep `watch/getState` compatible for existing language clients and occasional explicit reads; the GUI neither saves/restores their mutable watch rate nor calls `stopWatching` on them. The effective value already exists on the mono `outputBus`. Publish current native base and current overall amount on a separate two-channel observation bus; preserve `outputBus/asBus/asMap` semantics. The GUI reads all three measured values through the native control observation broker. `getMap/getLive` is not required for this output-bus display.

[SignalCaptureBroker](../../awb-shell/src/signalCaptureBroker.mjs) remains the shared audio/control-history path for scopes and other audio consumers. The independently verified direct shared-control API is implemented separately in [ControlObservationBroker](../../awb-shell/src/controlObservationBroker.mjs), with one sparse reader per local server and 8/15 Hz latest-value leases. It creates no ScopeOut tap, copies into JS-owned arrays and leaves existing audio/history routes unchanged. Installed scsynth and supernova passed the precursor probe; the finished GUI's live engine qualification remains a separate gate.

Registered connection records retain amount and curve. Registry `content` currently omits those values. Plain bus routes are currently retained mainly as Synth references; owned writer records have IDs/nodes/definition/control information. Public mutation methods for source amount/curve, complete serializable route metadata, compact output-bus subscriptions, shell transport and the GUI must be added. Avoid direct GUI writes to private collections or route Synth controls that leave the language metadata stale.

## Required language additions

Add public `setModulationAmount(id,value)` and `setModulationCurve(id,value)` methods, or an equivalently clear validated combined method. They resolve an existing standard route, validate using AWParam's existing amount/curve rules, update its route Synth and the retained record, and emit a configuration change. Removing a source or closing its owner during an edit returns a specific failure. Pending records either reject editing until connected or retain the edited values consistently through connection completion; implement one explicit policy and test it. Per-source edits are immediate in this slice; do not add hidden timed ramps or change the existing global transition signature.

Expose plain routes and registered connections through serializable records containing id, kind, sourceID/label, bus, producer/node reference, amount, curve, status, error and capabilities. Custom writers declare their supported controls. Runtime node/bus IDs remain runtime observations; do not persist them as portable configuration. Retain an operation to obtain the metadata snapshot and notifications when it changes. Route setters must participate in the owning Tool's existing configuration/state persistence where that configuration already represents the route; do not claim route preset support if it is not implemented.

AWParam remains a composable class rather than becoming a ToolInstance per knob. Bind GUI operations through the existing owning ToolInstance plus parameter key. A language convenience entry such as `param.gui` should select/open that binding using a small adapter and normal Tool GUI lifecycle. For an AWParam without an owning Tool, use an explicit lightweight inspector Tool adapter borrowing the param; closing the inspector must not free it. Qt-based Tool GUIs follow ToolGUIContract; Electron views follow the existing Chain/Rack shell attachment lifecycle. A plain AWParam is never a Tool. The implementation must follow the applicable host attachment conventions and include a concrete sclang example for both embedded and standalone use.

## Bridge and state contract

Define a renderer-independent model with three distinct kinds of state:

1. Metadata/configuration: ControlSpec, display information, targets, curves, source topology/capabilities and statuses.
2. Observation: measured current native base, current signed overall amount and current effective output from direct shared-control reads, plus generation/sequence and binding freshness. Targets and transition commands arrive as independent change events. Each observed field is sent only when changed; static base/amount therefore generate no recurring payload. Every value has a declared native or normalized domain.
3. Local UI: editing text, focus, panel expansion, selected renderer and pending operation tokens.

Resolve commands with owning host/ToolInstance identity and param key, not a global name or arbitrary node ID. Reject stale bindings after owner closure/reboot. Commands cover base/global amount/global curve and standard source amount/curve. Preserve duration/curve support on existing global setters; normal knob edits use duration 0. Bridge handlers validate fields and return request-correlated accepted/rejected results. Do not automatically change MIDI/takeover semantics.

Local mouse/keyboard edits paint the affected control on the next display frame, independently of incoming observation cadence. A base edit emits only a base change, and an amount edit only an amount change; include duration/curve/revision when required by that change. Curve and source edits likewise emit only their changed fields. Other clients and genuine language-origin changes receive these parameter-level deltas. Suppress redundant own-origin command echoes; acknowledgements/rejections still reconcile the initiating client. Observation never creates another edit. Reconnect obtains one fresh snapshot and binding epoch; do not replay obsolete gestures onto a new engine instance.

Full ControlSpec, source topology and configuration snapshots are for initial connection/recovery or explicit export. Subsequent metadata and topology changes are deltas. AWBCoreTool currently responds to target changes by collecting every parameter configuration and calling `instance.updateState` after a 20 ms gate. Change this interaction path to update the affected configuration entry and publish its delta. Preserve persistence and full-snapshot recovery, but do not rebuild or transmit the whole parameter list on every drag. Verify this at the actual Tool bridge, not only in the React widget.

Recurring output observation uses control-bridge leases shared across viewers, never an AWParam state reply per widget. One viewer closing must not interrupt another or alter a language client's watch setting. Observe visible outputs at 8/15 Hz, default 15 Hz; release or suspend hidden subscriptions under an explicit policy. At each publication keep only the latest scalar per output, deduplicate unchanged values and batch changed outputs with one batch header. Establish the parameter-to-bus/index mapping on binding; do not repeat names, specs, curves, topology, base/amount or command serials alongside every scalar. Bound queues and validate generation/sequence so stale values cannot attach to reused buses. A liveness/heartbeat mechanism must distinguish an unchanged valid output from a disconnected feed without resending all values.

Use a sparse, bounded union of subscribed control bus indices per local server. The GUI requires no waveform history transport, ScopeOut tap or round trip through sclang for each value sample. Server modulation continues at control rate while the browser displays current measured values. The shared-control API does not provide an atomic multi-bus transaction; this is display telemetry rather than a block-coherent processing feed. Mark unavailable values explicitly. Teardown releases observation resources, retaining borrowed params, producers and buses.

## Rendering requirements

Use requestAnimationFrame for prompt local interaction: pointer drag, numeric commit and keyboard edits paint on the next display frame. Use a separate elapsed-time 8/15 Hz gate for incoming modulation/output observations, aligned to display frames. Coalesce both paths so the same widget is not painted twice in one frame. The slower telemetry gate must never throttle the editable knob or amount ring. Do not add CSS transitions that create intermediate animation frames. Deduplicate drawing at displayed precision without quantizing OSC edits, SC values or preset data. Update numeric labels only when their formatted text changes.

React owns construction, structure, focus and configuration changes. Live observation must update only the affected widget/primitive through narrow subscriptions or imperative handles; it must not rerender the whole panel. SVG updates existing stroke geometry/attributes. Canvas2D caches static artwork and redraws only affected controls/regions, using one canvas per panel rather than one per knob. Canvas interaction requires accessible DOM numeric/range controls with equivalent keyboard behaviour, not a pointer-only hit map. Preserve pixel alignment and window scaling/DPR behaviour in both variants. Avoid layout reads in the paint loop and rebuild caches only for actual structure/size/theme changes.

The amount ring follows measured current overall amount. The thin output arc spans measured current base to measured effective output. During local gestures the editable control paints immediately; the next measured value reconciles it. Timed transitions remain in SC; the browser does not paint a reconstructed ramp. All four combinations—static base/modulated output, ramping base, ramping amount and both—must render correctly. Opacity mode fades a separate output layer while leaving names, input fields and the editable base readable.

## Comparison evidence

[Opacity costs](../../awb-shell/docs/scope-opacity-costs.md) and [opacity scaling](../../awb-shell/docs/scope-opacity-scaling.md) are useful prior measurements, not a pricing model for this widget. In the scaling test, 128 widgets fanned out from 16 control sources; at 48 px they added roughly 4 points of one core at 8 Hz and 7 points at 15 Hz above 16 widgets. Timed style-assignment work omitted later browser rendering, and helper CPU included GPU-helper CPU rather than measured GPU execution. The older canvas meters had different shapes/functions/areas. There is no existing identical modulation-arc comparison. A Bitwig-style line has not been shown to be too expensive.

Before polishing both renderers, measure the transport with 16, 32 and 128 independent AWParams, including static outputs and changing outputs. The old `watch(15)` path would generate 1,920 state replies/sec for 128 parameters before downstream batching; that is a workload calculation, not a measured failure. Verify that the new GUI path leaves periodic replies disabled, idle base/amount generates no recurring messages, and output delivery consists of compact batches. Record tap count, raw acquisition work, transmitted scalars/bytes/batches and cleanup.

Then benchmark identical base knob, amount ring, output arc, dimensions, labels, source feed and cadence in SVG versus Canvas2D. Add opacity only as a third output-cue condition. Measure 16, 32 and 128 widgets at 8/15 Hz, with stopped observation, feed-only and full-display baselines. Distinguish 16-source fan-out from equally many independent AWParams; record which mode each result uses. Exercise the source panel open/closed and base/amount automation separately from continuously modulated output.

Include all owned shell/renderer/helper process CPU, bridge/SC reporting costs, command latency and frame/update counts. Verify advancing values, actual rendered pixel changes and complete subscription cleanup. Hold window size, DPR, visibility, workload and record durations fixed; use repeated/interleaved phases and retain failures. Do not select a renderer using micro-timings of its JS hook alone. Combined audio deadline/headroom qualification uses the existing live comparison suite once the engine slot is available; no new full DSP sweep is required for this UI handoff.

## Acceptance and delivery

- A playable demo exposes several named AWParams with linear/exponential specs, negative/global amounts, multiple registered sources, a plain bus and a custom owned writer. Demonstrate calling the GUI from sclang and embedding the same control in a parent Tool panel.
- Base and overall amount edits change SC immediately; standard source amount/curve edits change the expected route and retained metadata. Changed base/amount and observed output stay correct during interrupted ramps and live modulation; estimated progress is labelled honestly. Unchanged base/amount is absent from recurring output payloads. No observation/command feedback loop occurs.
- Source names and process links remain truthful through pending validation, node free, disconnect, reconnect and owner closure. Unknown producers/custom capabilities remain explicitly labelled. Closing a view frees its bridge observation lease without freeing borrowed params or producers or changing existing AWParam watch clients.
- Keyboard/numeric editing, panel focus return and equivalent Canvas accessibility work. Normalized positions agree with ControlSpec mapping; output clipping and bipolar/signed cases are visible and tested.
- Changing one live value does not rerender/rebuild the whole panel or transmit its complete configuration list. Dragging paints on the next display frame at either telemetry cadence. Both renderers use identical compact input, coalesce display work and avoid redundant writes. Test independent field deltas, full-snapshot recovery, heartbeat, bus reuse and multiple-viewer lease teardown.
- Deliver focused SC and browser/protocol tests, comparison results with units/limitations, working sclang examples, source and the rebuilt artifacts actually consumed by the shell. Preserve legacy Param/AWBase and the active live set. Report implementation, tests, hardware qualification and remaining work separately.

Implementation order: validated language route metadata/setters and parameter-level configuration notifications; direct shared-control leases for measured base/amount/output and independent target events; early independent-parameter transport benchmark; usable SVG knob/rings and source panel; matching Canvas2D renderer; equal-input performance comparison; integrated live qualification when reserved.
